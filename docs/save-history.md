# Согласованность сейва и истории

Реализовано 4 октября 2026 года. Версия сейва — 11, схема базы сохранений — 2.
База мира редактора и дизайн не менялись.

## Как работает хранение

История хранится в `user://saves/games.db`, рядом с сессиями. Таблица
`save_history_nodes` содержит неизменяемые пакеты истории со ссылкой на родителя.
`save_history_players` хранит сводные показатели и бинарный снимок каждого
завершившего карьеру игрока. Снимок сохраняет имеющиеся атрибуты, личность,
развитие и карьерную статистику; вычисляемые кэши рейтингов исключены.

У текущей сессии есть `history_head`. Слот сохраняет этот указатель в
`save_slots.history_head` одной транзакцией с телом сессии. Запись пакета истории
также транзакционная: новый узел и все его игроки фиксируются вместе. Проверяются
BEGIN, отдельные записи и COMMIT. Слот может ссылаться только на существующий узел.

Межсезонье может записать новую ветку до ручного сохранения. Это не меняет
указатель уже сохранённого слота. Если приложение закрывается без сохранения,
старый сейв по-прежнему видит только свою историю. Незавершённая транзакция
откатывается средствами SQLite.

При загрузке старой точки сессия восстанавливает её указатель. Повторное
прохождение сезона создаёт другую ветку; прежняя история не перезаписывается.
Новая игра начинает с пустой истории. Сохранение в другой слот использует тот же
указатель, без копирования всех исторических игроков. Удаление исходного слота
не удаляет данные, на которые ссылаются другие слоты.

## Ошибка записи

Если запись истории не удалась, весь пакет остаётся в памяти в виде отдельных
снимков для повторной попытки. Сохранение сессии не допускается, пока её история
не записана. Продолжение симуляции также сначала повторяет запись. При смене
сезона основные расчёты уже завершены; возвращается ошибка с предложением
повторить сохранение, а не повторно выполнить всё межсезонье. Игра показывает
сообщение и останавливает автосимуляцию. Старый сейв остаётся доступен.

При загрузке другой точки или завершении сессии несохранённая ветка покидает
текущую игру. Подробности доступны по ID через `CareerArchive.open(slot)` или
`open_head(history_head)`, без загрузки всей истории в активные пулы.

## Старые сохранения

SQLite-сейвы прежних версий и JSON продолжают читаться. При загрузке версии
до 11 старый `<slot>_history.db` читается без изменения его таблиц. Переносятся
завершившие карьеру до сезона загружаемого сейва; записи с ID действующих игроков
исключаются. При следующем успешном сохранении указатель импортированной истории
попадает в новый сейв. Старый архивный файл сохраняется. Старый JSON удаляется
только после успешной записи нового сейва.

Прежний формат не содержал идентификаторов веток и мог уже смешать разные игры.
Фильтры отсекают известное будущее и коллизии с активным пулом, но не позволяют
достоверно восстановить происхождение уже смешанных старых записей. Отсутствующие
в старом архиве атрибуты и периоды карьеры не восстанавливаются.

## Что остаётся

- Подключить архив к поиску и карточке игрока в интерфейсе.
- Сохранять все периоды принадлежности клубам, включая нулевые выступления и
  возврат в тот же клуб, полный журнал переходов и исторические названия.
  Снимок сохраняет имеющиеся данные, но не исправляет их прежнюю неполноту.
- Добавить безопасную уборку узлов, которые больше не доступны ни одному сейву
  и текущей сессии. Сейчас они остаются в базе; автоматическое удаление истории
  не применяется. Это увеличивает размер базы при многократном ветвлении.
- Завершить внутреннюю валидацию загружаемой сессии. Сейчас добавлены отказ для
  неизвестных будущих версий, проверки типов верхних секций и ссылки на историю.

## Проверки

`tests/game/test_save_history.tscn` проверяет старые точки, смену и удаление слотов,
новую сессию, реальное и повторное межсезонье, сохранность снимков, миграцию старого
архива и ошибки записи. Ошибки INSERT и отложенной проверки внешнего ключа при
COMMIT намеренно вызываются SQLite-триггерами в отдельной тестовой базе.

Запуск в изолированной копии:

```powershell
./tools/run_load_benchmark.ps1 -TestScene res://tests/game/test_save_history.tscn
./tools/run_load_benchmark.ps1 -TestScene res://tests/game/test_save_store.tscn
./tools/run_load_benchmark.ps1 -TestScene res://tests/game/test_match_day.tscn
```

Результаты: история — **96 passed, 0 failed**; SaveStore — **37 passed, 0 failed**;
матчевый день и межсезонье — **39 passed, 0 failed**. Ожидаемые сообщения SQLite
о принудительном отказе INSERT/COMMIT в тесте истории не считаются неожиданными
ошибками; все остальные ошибки скриптов и SQLite отклоняются запускателем.

Диагностический прогон 10 клубов до конца сезона 100 завершён за 144,081 с.
Отчёт: `tests/performance/results/clubs-10-seasons-100-20261004-005556-468.json`.
В сезоне 100: 5209 архивных игроков; проверяемая идентичность, снимок и 4 строки
статистики игрока ID 475 не изменились с контрольной точки сезона 10.
Чтение его данных — 0,885 мс; сохранение — 231,840 мс, загрузка — 120,519 мс.
Пик памяти Godot — 107,5 МиБ. Замер выполнен после перехода на ветки истории,
до последнего исключения временного кэша из снимков; этот шаг отдельно проверен
тестом истории. Разница со старым прогоном не доказывает ускорение симуляции.

Статус длинного прогона — `completed_with_squad_violations`: сохранились прежние
29 записей о нарушениях позиционного состава. Сохранение указателя истории,
ID и данные архивного игрока прошли проверки. Целостность всей симуляции и
производительность 1000 клубов × 100 сезонов этим результатом не подтверждены.
