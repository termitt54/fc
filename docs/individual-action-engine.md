# Индивидуальная симуляция матчей, API 3

Исторический отчёт предыдущего этапа. Текущие составы, позиции и правила ассистов описаны в [модели 3-2-2, API 4](team-model-322.md).

Поле 60×40 м, ворота 5×2 м, 50 минут, без офсайда. На каждой стороне действуют
только восемь вышедших на поле футболистов. Запасной получает влияние после
фактической замены. Реализации C++ и GDScript проверяются на одинаковых составах
и состоянии генератора случайных чисел.

## Что изменено

Коллективный расчёт шансов атаки заменён последовательностью владений,
перемещений, передач, приёмов, единоборств и ударов. У участников есть координаты,
скорость, запас сил и назначение при обороне. CA, PA, репутация и талант страны
не являются входами расчёта эпизода. Они сохраняются для генерации, развития,
интерфейса и экономики.

Состав распределяется по ролям совместно: алгоритм ищет лучшее назначение всего
набора игроков, вместо последовательного выбора, который мог отдать нападающего
на фланг и оставить центр атаки менее подходящему партнёру. Это выбор участников,
а не показатель силы, используемый для определения счёта.

Тактика меняет расположение, направления передач, склонность к ударам и темп.
Тренер влияет на выбор продолжения и организацию опеки. Плоского бонуса тренера
к голам или силе команды нет. Защитники получают разных опекаемых соперников;
ближайший выходит к мячу, остальные сохраняют прикрытие.

При продвижении мяча центральные полузащитники поддерживают атаку, фланговые
могут входить ближе к воротам, крайние защитники подключаются. Центральные
защитники поднимают линию осторожнее. Это реальные целевые координаты и пробег,
а не заранее назначенная доля голов каждой позиции. Вратарь при обычном
возобновлении остаётся у своих ворот; к центру ставится только разыгрывающий
начальный удар.

## За что отвечают навыки

| Навык | Действие |
|---|---|
| Завершение | Погрешность направления и скорость удара, возможность пробить под давлением |
| Пас | Погрешность точки назначения передачи |
| Техника | Радиус уверенного приёма и время обработки мяча |
| Дриблинг | Прохождение конкретного ближайшего соперника |
| Защита | Противодействие обводке, блокировка, перехваты, риск нарушения |
| Быстрота | Метры в секунду при перемещении, рывке и подборе |
| Сила | Контактные и верховые единоборства |
| Выносливость | Расход сил по времени и нагрузке |
| Восстановление | Возвращение готовности между матчами |
| Подачи и стандарты | Точность навеса и исполнение свободного удара |
| Пенальти | Точность удара с точки; отдельно от обычного завершения |
| Реакция | Задержка ответа вратаря на удар |
| Надёжность рук | Фиксация мяча либо отскок после отражённого удара |
| Выбор позиции | Исходная позиция вратаря относительно мяча и ворот |
| Выходы и один на один | Выдвижение, сближение с нападающим, перехват навеса |
| Верховая игра | Единоборство за навес с добежавшим до мяча нападающим |

Победа в единоборстве остаётся вероятностной. При равных навыках шанс 50%; при
разнице 10 пунктов — около 82% против 18% до влияния усталости и настройки
единоборств. Один пункт около равенства меняет шанс примерно на 3,7 процентного
пункта. Это не обещание одинакового изменения итоговой вероятности победы команды.
Дистанция, свободное пространство, соперник и усталость определяют, сколько таких
действий игрок сможет выполнить.

## Совместимость и запуск

Обновление Windows-библиотеки: `fc_sim_core_v3_1.windows.template_release.x86_64.dll`.
Нужно перезапустить игру и открытый редактор Godot. Уже загруженная библиотека
не заменяется в работающем процессе. При недоступности API 3 используется
существенно более медленный GDScript.

Существующие игроки, архивные матчи и результаты не пересчитываются. Новые
счётчики действий входят в отчёт матча и статистику. Полный журнал действий
включается для диагностики, а не записывается для всех матчей обычного сейва.

Настройки матчей имеют версию 7. При чтении старого файла темп, склонность к
ударам, точность и скорость удара, а также сила встречных единоборств переходят
к новым базовым значениям. Настройки усталости, восстановления и замен
сохраняются. Значение 100% у новых контролов точности и темпа означает базовый
уровень настройки, а не стопроцентное попадание или реализацию.

Кэши не объединяют разные записи футболистов только из-за совпадения ID.
Добавлена отдельная проверка этого случая; в тестовых поколениях двух стран
используются разные диапазоны ID, как в настоящем мире игры.

Это дискретная пространственная модель, не непрерывная 3D-физика. Она моделирует
действия и их участников; не гарантирует отсутствие сенсаций или идеальную
реалистичность любого сочетания настроек. Старые параметры результативности
потребовали миграции, поскольку теперь управляют действиями и траекторией мяча,
а не прямой вероятностью гола.

полузащитники — только 25. После добавления подключений в 1000 равных матчах:

Полузащитники забили 583. Доля форвардов — 87.1%.
Распределение всё ещё смещено к форвардам; центральные полузащитники и защитники
забивают редко. Полное соответствие распределению реального футбола не подтверждено.

### Производительность

Изолированная копия пользовательского мира: 128 клубов, 9 087 игроков, 64 матча за день,
Ryzen 5 3600. Медианы времени самой симуляции (без следующего кадра):

| Режим | мс |
|---|---:|
| Синхронно, без UI | 588.1 |
| Порционно, без UI и ограничения FPS | 591.0 |
| С UI, без ограничения FPS | 643.6 |
| Порционно, 60 FPS | 1154.3 |
| С UI, 60 FPS | 1175.6 |

Предыдущая коллективная модель: примерно 422 мс синхронно и 675 мс с UI при 60 FPS.
Новая модель медленнее. При 60 FPS заметны ожидания между порциями основного потока;
время одного матча нельзя выдавать за время дня. Хеши sync/sliced/UI совпали.
