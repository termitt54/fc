# Конструктор клубного кубка — 12 ноября 2026

Кубок остаётся элементом существующего турнира. Его этапы и правила хранятся
отдельно в `cup_formats` (миграция 31). Строки дивизионов, их правила,
генератор календаря и алгоритм повышений/вылетов не изменяются.

## Как настроить

Текущий редактор использует **слоты участников**. Укажите число команд этапа:
столько слотов и появится. Прошедшие предыдущий этап занимают первые слоты
автоматически; для каждого нового участника выберите дивизион и место в его
общей итоговой таблице. Пример: этап 1 на 8 команд с выходом 4; этап 2 на 16
команд получает 4 зарезервированных слота и 12 слотов для новых мест.
Изменение числа проходящих или порядка этапов пересчитывает свободные слоты.
Дубли мест, пустые слоты и недостаточная вместимость блокируют сохранение.
Слоты не задают пары матчей: пары и группы формируются выбранной жеребьёвкой.
Старые правила отбора поддерживаются в сохранённых играх; при открытии
старого шаблона редактор готовит черновик слотов, который следует проверить
перед сохранением. Изменения черновика не затрагивают базу до сохранения.

1. Открыть существующий турнир и добавить либо раскрыть «Кубок».
2. Нажать «Настроить этапы, участников и жеребьёвку».
3. Включить проведение кубка и добавить этапы сверху вниз.
4. На каждом этапе отметить дивизионы, из которых входят **новые** участники.
   Можно включить всех их членов или выбрать клубы вручную.
5. Выбрать группы либо плей-офф и настроить проход дальше.
6. Сохранить кубок. Для использования изменённого шаблона начать новую игру.

В конструкторе действует отдельный черновик: закрытие и отмена не сохраняют
правки. Кнопка «Сохранить кубок» записывает только кубок; изменения его этапов
не зависят от кнопки сохранения карточки родительского турнира.

Пример: низший дивизион входит в отбор, следующий — на втором этапе,
оставшиеся — на групповом этапе. Победители каждого этапа автоматически
добавляются в следующий. Один исходный дивизион можно подключать на нескольких этапах;
повторное включение уже участвовавшего клуба исключается автоматически.

### Отбор по итоговым местам

Для каждого этапа можно выбрать всех участников отмеченных дивизионов,
первые N мест, последние N мест, включительный диапазон мест, всех ещё
не участвовавших либо конкретные клубы. Правило применяется отдельно к
каждому отмеченному дивизиону по его общей итоговой таблице текущего сезона
с существующими критериями мест. Исходные таблицы не изменяются.

Один дивизион можно подключать на нескольких этапах. Например: этап 1 —
последние четыре места 4-го дивизиона, проходят двое; этап 2 — все ещё
не участвовавшие клубы этого же дивизиона плюс двое прошедших автоматически.
Выбывшие на первом этапе не возвращаются. Отбор разрешается по актуальным
таблицам при входе в этап, до межсезонных повышений и вылетов.

## Правила этапов

- **Плей-офф:** один или два матча в паре; этап продолжается, пока не останется
  заданное число команд. Для одного раунда нужно задать соответствующее число
  проходящих. Последний этап должен оставить одного чемпиона.
- **Группы:** число групп, один/два круга и число проходящих из каждой группы.
  Неравные размеры групп допустимы, если в каждой есть минимум две команды
  и хотя бы одна выбывает. Очки 3/1/0; критерии — очки, разница мячей,
  забитые мячи, ID клуба при полном равенстве.
- **Жеребьёвка:** свободная либо посев по Elo, репутации или уровню дивизиона.
  Для плей-офф сильные встречаются со слабыми; группы заполняются змейкой.
  При равенстве показателя используется предварительное перемешивание.
- **Неполная сетка:** автоматические проходы. При посеве приоритет у первых
  команд списка, при свободной жеребьёвке — случайный.
- **Два матча:** суммарный счёт, без правила выездного гола. При равной сумме
  дополнительное время и пенальти в ответной игре. Ответные игры считаются
  GDScript-движком с учётом счёта первой игры; остальные могут использовать C++.
- **Календарь:** минимальный день старта этапа, интервал матчей, нейтральное
  поле. Кубок ожидает завершения всех клубных дивизионов и их плей-офф.
  Календарь дивизионов не переносится; кубковые матчи разных кубков разводятся
  по занятости участвующих клубов. Сборные ждут завершения клубных кубков.

## Сезоны и сохранения

Состав каждого исходного дивизиона читается из сессии после повышений/вылетов.
При ручном выборе участвуют только отмеченные клубы, которые остаются членами
отмеченных исходных дивизионов. Новые клубы автоматически входят только в режиме
«все клубы». Структура проверяется до запуска игры и до смены сезона; ошибка
в числе участников останавливает действие с пояснением до изменения сезона.

Периодичность и стартовый сезон наследуются от родительского турнира. Пропуск
розыгрыша не добавляет чемпиона. Старые игры без настроенных кубков продолжают
работать по прежней схеме. Изменения world DB автоматически в текущий сейв
не импортируются.

В сейве находятся этапы, участники, жеребьёвка и состояние собственного RNG.
Генератор кубка не расходует RNG жеребьёвки дивизионов. Матчи используют общий
матчевый движок, статистику игроков и дисциплину кубка. Итоговый победитель
записывается в историю, снимок этапов сохраняется в архив сезона.

## Границы текущей версии

Этапы образуют последовательную цепочку. Проходят все победители предыдущего
этапа; произвольные ветви квалификации, утешительные сетки, ручные пары,
запрет повторных встреч и дополнительные ограничения жеребьёвки не добавлены.
Нет отдельных призовых за этапы, серий до нескольких побед и отдельной сетки
суперкубка. Групповые очки и порядок критериев пока фиксированы.

## Проверка

`tests/game/test_cup_competition.tscn`: 204 проверки. Смешанные этапы,
поэтапный вход дивизионов, сетки 3/5/100/164/200 клубов, проходы,
ручной выбор, неизменность исходных дивизионов, сохранение между раундами,
SQLite, отмена формы, реальная синхронная/асинхронная симуляция,
двухматчевые пары, периодичность, архив и следующий сезон.

Тест запускается только с отдельным `user://`, имя которого содержит
`fc-cup-tests`; интеграционные фикстуры не используют пользовательские сейвы.
Окно конструктора отрисовано и осмотрено при 1280×900.
